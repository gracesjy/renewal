## 선행 준비
먼저 Docker Desktop 이 설치되어 있어야 하고, 실행한다. 또는 Docker Desktop 역시 WSL 기반이므로 다음과 같이 할 수도 있다.

![2026-08-06-091311.png](/assets/images/2026-08-06-091311.png)

Docker 를 끄려면 다음과 같이 한다.
```powershell
wsl --terminate docker-desktop
```
Docker 를 백그라운드에서 켜려면 다음과 같이 한다.  윈도우에서 Docker Desktop 을 클릭해서 실행해도 되고, 서비스로 등록해도 되지만 항상 쓰지 않는다면 서비스로 자동 기동을 하지 않는 것을 추천한다.
```powershell
wsl -d docker-desktop true
```
![2026-08-06-091717.png](/assets/images/2026-08-06-091717.png)

## Docker 기본 명령어
PowerShell 이나 Command (cmd.exe) 를 기반으로 작업하는 것도 알아 두면 좋다.  기본적으로 Docker Desktop 으로 해도 되지만 Docker 의 새로운 이미지나 컨테이너를 만드는 것은 Docker Desktop 보다는 PowerShell 이나 Command (cmd.exe)가 더 나을 수 있기 때문이다.

### Docker 배포판 이미지 및 컨테이너 만들기
AI 에게 질의해서 최신 배포판 같은 것을 알려달라고 하면 다음 예(오라클 데이터베이스)와 같이 알려 준다. 기본적으로 실행하면 이미지를 자동으로 다운로드 하고 그 이미지 기반의 컨테이너를 만들어 기동 시켜 준다.  한번 컨테이너를 만들면 다음에는 Docker Desktop 에서 실행 버튼만 누르면 되기 때문에 편리하다.

```powershell
docker run -d --name oracle23c -p 1521:1521 -e ORACLE_PASSWORD=alex1020 gvenzl/oracle-free:latest
```
![2026-08-06-092320.png](/assets/images/2026-08-06-092320.png)

### Docker 컨테이너 조회
ps -a 는 정지되어 있는 것 까지, ps 는 실행 중인 것들을 보여준다.
```powershell
docker ps -a
```
아래 이미지의 Status 부분에서 Exit 는 정지 상태이다.
![2026-08-06-092420.png](/assets/images/2026-08-06-092420.png)
### Docker 컨테이너 멈추기
docker stop my-web-app 로 이름으로 멈출 수도 있고 Container ID 로 멈출 수도 있다.
```powershell
docker stop bdae_postgres_vector
```
![2026-08-06-092736.png](/assets/images/2026-08-06-092736.png)

### Docker 컨테이너 실행
docker start my-web-app 또는 docker start 982ce3c6b24a 로 Container ID 로 실행 시킬 수 있는데, Container ID 는 docker ps -a 로 확인할 수 있다.  
```powershell
docker start bdae_postgres_vector
```
![2026-08-06-093040.png](/assets/images/2026-08-06-093040.png)

## Container 작업 후에 나만의 이미지 저장 및 배포
내려 받은 기본 이미지 및 컨테이너에 작업을 하고 개발을 한 다음에 이 기반에 자신의 프로그램을 넣어서 배포를 하려면 다음과 같이 한다.

### 1. 배포 또는 백업하려는 컨테이너 확인
```powershell
docker ps -a
```

```powershell
118bac700ca8   container-registry.oracle.com/database/free:latest   
               "/bin/bash -c $ORACL…"   8 hours ago     Up 2 hours (healthy)         
               0.0.0.0:1521->1521/tcp, 0.0.0.0:1500->5500/tcp   oracle-23ai-free
```

### 2. Commit 
위의 것을 배포/백업 하려면 Commit 을 먼저 해 주어야 한다. 이때 oracle_bdae:0.5 등은 이름과 버전을 적어 주는데, 이것은 자신의 배포판에 대한 이름과 버전이 된다.
```powershell
docker commit -p 118bac700ca8 oracle_bdae:0.7
```

### 3. 파일로 저장 (.tar)
이제 파일로 저장해서 USB 같은 곳에 넣어서 배포/백업 하면 된다.
```powershell
 docker save -o oracle_bdae_0.7.tar oracle_bdae:0.7
```

## Docker 배포/백업 파일 Import 하기
### 1. Image Import
tar 파일을 Docker Image 로 Import 한다.  그러면 아래처럼 Image 가 생성 된다. 이 이미지는 아직 실행 단계가 아니다.  
```powershell
docker load --input oracle_bdae_0.7.tar
```

![2026-08-06-094027.png](/assets/images/2026-08-06-094027.png)
### 2. 컨테이너 만들기
앞서 일반적인 배포판들 (PostgreSQL, Oracle 23C 등)은 docker run ... 안에 이미지 다운로드부터 컨테이너 구성까지가 모두 들어 있지만, Import 인 경우에는 스스로 만들어 주어야 한다.  그러나, 사실 똑같다. 왜냐하면 없으면 자동으로 다운로드 하기 때문이다. 다만 그 Repository 에 자신이 만든 것이 올라가 있지 않기 때문에 자동으로 다운로드가 아니라 위의 Import 를 해서 Image 를 넣어 준 다음 그것으로 실행 시킬 뿐이다.

다음을 보면 --name 은 컨테이너 이름이고 Image 의 이름이 아니다. 주의하자.  그리고 port 는 외부:내부 등으로 이미 사용중인 포트를 회피할 수 있는 것이고 맨 뒤의 oracle_bdae:0.7 은 위에서 Import 한 Image 의 이름과 버전이다.

컨테이너 내부 Port 는 일반적으로 어플리케이션의 디폴트를 사용해도 된다. PostgreSQL 은 5432 가 디폴트 포트이고 오라클은 1521 이다.  그렇지만 이미 PostgreSQL 이 떠 있다면 5432 포트는 호스트 PC 에서 더 이상 쓸 수가 없기 때문에 이때는 5433 등으로 바꾸라고 명령을 하는 것이다.  -p 5433:5432 로 하면 된다.

![2026-08-06-094914.png](/assets/images/2026-08-06-094914.png)

```powershell
docker run --name oracle_bdae -p 1521:1521 -p 5500:5500 oracle_bdae:0.7
```

### 3. 컨테이너 기동 확인
이제 Docker Desktop 의 컨테이너로 가면 기동 되었는지 확인할 수 있고, 위의 컨테이너 만들기는 최초 단 한번만 하면 된다.

## Docker 이미지 만들기 (JAVA)
Java 기반의 Docker 를 만드는 방법을 예시 한다.

### 1. 디렉토리를 하나 만들고 필요한 파일들을 모두 넣는다.
![2026-08-06-095259.png](/assets/images/2026-08-06-095259.png)

### 2. Dockerfile 을 준비한다.
디폴트로 Dockerfile 로 파일명으로 아래와 같이 편집한다. Java 기반이므로 먼저 Java 버전과 배포판을 찾아서 FROM 형태로 넣어둔다. EXPOSE 는 기본적으로 Export 하는 포트이다.  7000 포트, 12686 포트가 서비스 포트가 된다.

> ENV 는 환경 변수이고 이것을 통해서 PC 환경과 매칭 시킬 수 있다. 특히 환경 파일이나 로그가 바로 그것이며 파일명, 디렉토리 명 등을 환경 변수로 설치 위치에 따라서 변경하기 위함이다.

> 이미지의 WORKDIR 디렉토리를 만들고 그 이하에 copy 를 통해서 디렉토리에 있는 파일들을 복사하는 명령들을 넣는다.

> 마지막으로 java 기동 명령을 넣어 준다.

```text
FROM rtfpessoa/ubuntu-jdk8
EXPOSE 7000 12686

WORKDIR /userdata/glomis

ENV GLOMIS_CONF_DIR dev
ENV GLOMIS_STARTUP_XML oven_ahol_4ds_modbus-startup.xml
ENV PLC_MAP oven_ahol_4ds_modbus-plc-map.xml
ENV GEM_MAP gem-map.xml

COPY java.security /usr/lib/jvm/java-8-oracle/jre/lib/security/java.security 
COPY bcpkix-jdk15to18-1.71.jar 
   /usr/lib/jvm/java-8-oracle/jre/lib/ext/bcpkix-jdk15to18-1.71.jar
COPY bcprov-jdk15to18-1.71.jar 
   /usr/lib/jvm/java-8-oracle/jre/lib/ext/bcprov-jdk15to18-1.71.jar
COPY bcutil-jdk15to18-1.71.jar 
   /usr/lib/jvm/java-8-oracle/jre/lib/ext/bcutil-jdk15to18-1.71.jar

COPY getprocess_all /userdata/glomis/edge/bin/getprocess_all
COPY cpu_usage /userdata/glomis/edge/bin/cpu_usage
COPY uptime_s /userdata/glomis/edge/bin/uptime_s
COPY get_max_disk.sh /userdata/glomis/edge/bin/get_max_disk.sh
COPY get_cpu.sh /userdata/glomis/edge/bin/get_cpu.sh
COPY get_disk.sh /userdata/glomis/edge/bin/get_disk.sh
COPY check_process.sh /userdata/glomis/edge/bin/check_process.sh
COPY get_mem.sh /userdata/glomis/edge/bin/get_mem.sh
COPY get_max_mem.sh /userdata/glomis/edge/bin/get_max_mem.sh
COPY stop_one.sh /userdata/glomis/edge/bin/stop_one.sh
COPY process.sh /userdata/glomis/edge/bin/process.sh
ENV PATH=/userdata/glomis/edge/bin:${PATH}

COPY edgeAgentNew-0.5.1-jar-with-dependencies.jar 
  /userdata/glomis/edge/lib/edgeAgentNew-0.5.1-jar-with-dependencies.jar

CMD java -Dapp.name=glomis -Dopc.ua.pki.directory=/export/glomis/security 
    -Dlog.home=/export/glomis/log 
    -Dlogback.configurationFile=/export/glomis/config/logback.xml 
    -DbaseDir=/glomis -Dport=12686 -jar 
    /userdata/glomis/edge/lib/edgeAgentNew-0.5.1-jar-with-dependencies.jar
```

### 3. 이미지 생성
자, 이제 이미지를 생성한다. 이렇게 하면 이미지가 만들어 지고 Docker Desktop 에서 위에서 했던 것 처럼 이미지(Image) 탭을 눌러서 볼 수 있다.  

```powershell
docker buildx build --platform linux/amd64 -t edge_agent:0.54 .
```
![2026-08-06-095945.png](/assets/images/2026-08-06-095945.png)

### 4. 컨테이너 생성
이제 실행을 해 볼 차례이고 실행 후 서비스를 이용하게 된다. -v 는 환경변수를 이용한 매핑을 보여준다. 즉 호스트 PC 의 윈도우 디렉토리와 Linux 환경에서 구동하는 것 사이의 1:1 매핑을 하는 것이다. 

```powershell
docker run  --mac-address='02:42:ac:11:00:02' 
-v C:\glomis_setup\deploy\edgeAgent:/export/glomis --name edgeAgent --hostname atlas  
-p 12686:12686 edge_agent:0.54
```

### 5. Export
충분히 테스트 했다면 위의 ***Docker 배포/백업 파일 Import 하기*** 처럼 .tar 파일로 배포하면 된다. 물론 배포 할 때는 tar 파일과 docker run .. 배치 파일을 주는 것이 좋다.
